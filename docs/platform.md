## Installation

The manifest provides a stable ID, name, standalone display mode, planner start URL, theme/background colours, 192/512 px icons and a separate maskable icon. The production build generates a versioned service worker. HTTPS is required on a deployed origin; localhost is accepted for development. These requirements were checked against the [MDN installation guide](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

Chrome exposes an installation prompt when eligible. The app's install control uses that event where available and otherwise offers browser-specific guidance. Safari's Share → Add to Home Screen guidance is not represented as a tested installation path.

**Actually verified:** Google Chrome 154.0.8037.92 on macOS, using an isolated temporary profile and a visible browser window, against **https://coolerwalks.ch/** on 29 September 2026. To repeat against the public release, run:

```sh

```

For a local production preview, set `PWA_ORIGIN=http://127.0.0.1:4173`. Optionally set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an installed Chrome executable. Headless Chrome accepts installation but did not expose a standalone window in this environment; use a graphical session for this check. The test uses a temporary profile and does not access personal browser tabs or saved accounts.

## Offline behaviour

The interface and fonts install independently of city downloads. A visited city works offline after both its routing and map files have finished caching. Other cities are cached on visit, including a handoff after first worker activation. Both map and routing downloads must complete before that city can be used offline. Unvisited city data is not prefetched. No third-party tile or routing service is used. The first visit still requires a connection; interrupted installation cannot guarantee offline availability. Cached data is historical, visibly dated in the method view, and has no live closure or weather feed. Browser storage may be evicted. The app does not persist precise journeys.

Production testing blocked network requests, reloaded the page and verified route cards, the rendered map, waterside preference and an intermediate stop, then switched to the previously saved Basel map/routes. An unvisited Cambridge request correctly failed offline; after reconnecting, selecting Cambridge restored both its map and routes. The test also verified that Cambridge had not been unnecessarily precached. Chrome 153's network emulation resets `navigator.onLine` after a cached navigation while retaining request blocking, so the test reapplies the documented network-state override for the banner check. Static cache matching ignores `Vary` because these public, same-origin build files do not vary by request origin; this was necessary for cached module/CSS requests to survive offline reload under Vite's preview headers.

## Performance and release limits

Each city has a separate processed map/model bundle. Expanded data totals approximately 182 MB uncompressed across all four cities; only the selected city loads into the browser. For the website/PWA, additional city files are downloaded on demand, not all at installation. Default native builds package all four bundles for immediate offline use; the lite build includes Zurich and downloads selected areas. This makes routing independent of demo services and supports bounded offline use, but the bundle should be measured on lower-end phones and slow connections before release. Vite reports a large JavaScript bundle, primarily the map stack; code splitting and a smaller geometry format are the next performance work. The current screenshots use Chrome software WebGL rendering and do not establish mobile GPU performance.

The website is deployed at https://coolerwalks.ch/ with valid HTTPS, production security/cache headers and all five verified downloads. See [the hosting record](hosting.md) for exact source, DNS and validation.
